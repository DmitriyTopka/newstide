NewsTide: app map

A take-home guide to how the app is built. Reference route; snapshot of commit c0f897e, it can drift as the code changes.

What it is

A one-page newspaper for a crypto trader. You pick a coin, Long or Short and a timeframe. A small server on your machine reads about 30 news items, asks Claude for one verdict in a fixed shape, checks the answer against fixed rules, saves the run, and the page prints it: a pointing hand, an ink stamp, a headline and a bull, bear or hamster.

One action: pressing Get data

Reference route (3 stops)

  1. public/app.js, search addEventListener('submit': the form sends coin, plan and timeframe to the server and starts the 60-second countdown.
  2. server/index.js, search app.post('/api/analyze': validates the input, calls collect(), analyze() and check(), computes the cost from the token counts and saves the run.
  3. server/check.js, function check: the rules every answer must pass (stamp agrees with hand and plan, no percent, headline of at most 6 words, every step cites a real dispatch). Back on the page, showResult in public/app.js prints it.

To change this, start here

  • Add a coin: one entry in config/coins.json with its official feeds.
  • Add or remove a news source: config/feeds.json.
  • How the editor reasons: the SYSTEM text in server/analyst.js.
  • The rules for answers: server/check.js, with tests in test/check.test.js.
  • Stamp words, edition names, animals: stampWords and animals in public/app.js.
  • Model and data mode: MODEL and DATA_MODE in .env.

A practice to reuse

The goal was to check precisely that the model did what was meant. The plan turned that into checks you can run: a fixed answer shape (SCHEMA in server/analyst.js), rules that do not depend on the model (server/check.js), tests for those rules (npm test), and a saved trace of every run (runs/example-run.json). Nobody can verify a forecast in advance, but you can verify that the model followed your instructions and cited real sources. On the next project with an agent: write down what a correct answer looks like before building, then make a check for each part of it.

Run it again

npm start, then open http://localhost:3000. Tests: npm test.

Why sample and live data?

DATA_MODE=sample reads the saved snapshot in data/sample/ so results are cheap and repeatable; live reads the feeds now.
